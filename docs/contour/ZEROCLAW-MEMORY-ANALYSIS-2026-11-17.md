## 2. Кейс LegalPlat через призму кода: почему факты сохранились, а вывода не было

Разбор вчерашнего провала (16.11, диалог с Ram) по механизмам:

1. **Факты сохранились** — `memory_store` → brain.db. Слой L2-хранения работал безупречно: агент нашёл все материалы.
2. **Консолидация работала, но не туда** — `consolidate_turn` сливал эпизоды в эпизоды (обобщения фактов), а не в суждения о компании. В коде нет понятия «вывод, который готов защищать» — консолидация не различает факт и тезис.
3. **Инжект не гарантировал нарратив** — релевантностная выборка (5 записей) может не поднять образ компании в контекст конкретного ответа. Core-памяти не имеют always-load.
4. **Граф пуст** — из чего было бы структурно расти осмысление, не было в принципе: 0 узлов при включённом auto_capture.
5. **Уровня L3 в zeroclaw нет вообще** — ни нарратива, ни очереди предложений, ни ратификации. Вчера это закрыто контуром файлами (wiki-страница + image-pending + правила в каноне). Это доказывает: концепт возможен, но носитель — файлы, не память рантайма.

**Вывод кейса:** ZeroClaw умеет *хранить* и *поднимать похожее*. Не умеет ни *стратифицировать значимость*, ни *строить суждения над фактами*, ни *согласовывать суждения с человеком*. Именно это и есть недостающая «полноценная память».

## 3. Гэпы против концепции семи пунктов

| Пункт концепции | Что в zeroclaw сегодня | Чего нет |
|---|---|---|
| 1. Нарратив-вершина, меняет человек | ничего | Нет типа «суждение/версия», нет механизма ратификации, нет always-load идентичности |
| 2. Архив опыта | brain.db + консолидация | есть, работает |
| 3. Очередь предложений | ничего (контур: файлы) | нет proposals-сущности, нет статусов, нет receipts |
| 4. Граф — инфраструктура, не голос | KG-модуль + инструмент, **0 данных** | нет потока наполнения, нет provenance к эпизодам, нет decay-весов в поиске графа, нет би-темпоральности |
| 5. Затухание с аудитом | decay — скоринг релевантности (не семантика); `superseded_by` — версионирование записей | нет связки «ратификация → затухание», нет находимости отвергнутого как класса |
| 6. Ядро-регулятор | core-категория памятей (не стареет), snapshot-экспорт | core не инжектится гарантированно; нет полномочий на уровне памяти (кто что может менять) |
| 7. Цена изменения как критерий уровня | нет | нет стратификации по дороговизне изменения |

## 4. Целевой вид (концептуальный, внутри форка zeroclaw)

**Принцип:** не тащим чужую базу данных. SQLite-граф уже в коде (`knowledge_graph.rs`), SQLite-память уже в коде, консолидация уже в коде. Достраиваем **механизмы поверх своего**, алгоритмы берём у grafeo-notebook как **идеи**, не как код.

### Отображение уровней на механизмы (целевое)

- **L0 контекст** — существующий session/turn-механизм. Не трогаем.
- **L1 рабочий стол** — воркспейс-файлы (drafts, wiki-staging). Не трогаем.
- **L2 архив** — brain.db (эпизоды) + **оживлённый граф**: узлы-сущности и связи с provenance на эпизоды; наполнение — из существующей консолидации (LLM-извлечение атомов, как у gbrain — без тяжёлых OpenIE/NER из grafeo, это упрощение) + explicit capture агента.
- **L2.5 очередь предложений** — новая таблица `proposals` рядом с памятью: дельта-суждения со статусами и receipt-цепочкой (идея Panella: писатель ≠ ратификатор — в нашем контуре второй ключ — оператор).
- **L3 нарратив** — каноническая версия суждений; в рантайме — как core-записи с гарантированным инжектом (достраиваем `memory_inject.rs`: always-load для pinned/core нарративных записей — механизм маленький, проверено место); в контурной части — wiki-страница, которую ратификация обновляет.
- **Ядро-регулятор** — core-памяти + полномочия (policy_gate уже есть — расширяем с content-screening на operation-authorization: агент propose-only).

### Что берём у grafeo-notebook как алгоритмы (не код)

1. **Чанкинг с контекстом** и инкрементальность (signature/hash, не пережёвывать всё) — идея для ингеста в граф.
2. **Каскад приоритетов** (дешёвые фильтры → дорогие LLM) — идея для извлечения атомов: сначала детерминированные правила, LLM — только на неуверенном.
3. **Центральность с затуханием** (PPR с decay-весами) — идея для ранжирования кандидатов в очередь предложений: не частота, а структурная значимость × свежесть × ратификационный статус.
4. **Би-темпоральность** (valid time + transaction time) — идея для версионирования узлов: «когда было истиной» vs «когда узнали».
5. **Dream-цикл как фазовая консолидация** — идея для ночной/недельной обработки: lint → консолидация → затухание → отчёт (у нас уже есть hygiene+self-review-крон — сращиваем).

### Что делаем проще, чем grafeo

- Без отдельной графовой СУБД: расширяем `knowledge_graph.rs` (SQLite FTS уже там).
- Без онтологического NLP (OpenIE/NER-сервисы): LLM-извлечение атомов с бюджетом (как gbrain), детерминированный слой — минимальный.
- Без отдельного retrieval-сервиса: поиск по графу — расширение существующего `recall` (смешанный скор: эпизоды + узлы).

## 5. Варианты развития (для обсуждения, не для выбора сейчас)

**Вариант A — «Добудить дремлющее» (в память zeroclaw всё).**
Расширить `knowledge_graph.rs` (provenance, decay-веса, би-темпоральность, типы под нарратив), добавить `proposals`-таблицу + receipts, always-load нарратива в inject, полномочия в policy_gate. Плюс: один носитель, L3 — рантайм-уровень. Минус: объём работ в крейте Experimental-тир; риск-ревью апстрим-влияния (форк-специфика — держим в контурных модулях, не ломая апстрим-поверхность).

**Вариант B — «Файлы как есть» (канон несёт L3, zeroclaw несёт L2).**
То, что работает с 16.11. Плюс: ноль работ в рантайме. Минус: очередь/receipts на файлах непроверяемы, нарратив не гарантирован в контексте, граф пуст и будет пуст.

**Вариант C — гибрид поэтапно (предварительно мой фаворит).**
Сейчас — B (уже работает). Первый шаг в код — только два узких места: (1) always-load нарративных core-записей в `memory_inject.rs` (маленький, изолированный патч), (2) `proposals`-таблица + статусы (контурная схема, без апстрим-лица). Граф-доработки (provenance, decay, би-темпоральность) — следующим эпиком после первых живых прогонов очереди. Критерий перехода: дельта прошла полный цикл, receipt-цепочка проверена.

## 6. Чего не делаем (границы)

Не тащим GrafeoDB/отдельный сервис в контур памяти zeroclaw (algorithms — да, платформа — нет). Не строим approval-инструментов для агента. Не даём агенту self-ратификацию никаким путём. Не ломаем апстрим-поверхность памяти (наши расширения — за feature-флагами/контурной схемой).
