# Дриминг: исследование архитектур консолидации памяти (2026-11-18)

Источник постановки: Ram — «прежде чем внедрять (9-6), исследовать, как устроен
дриминг в других движках; синтезировать оптимальное поверх нашей базы».

## Обзор движков

### OpenClaw memory-core dreaming — наш прямой предок, самое детальное описание
(docs.openclaw.ai/concepts/dreaming, прочитано целиком 18.11)

- **Три фазы за прогон**: Light → REM → Deep. Light: сортировка/дедуп
  свежего краткосрочного материала, без долговременных записей. REM:
  рефлексия над темами/повторами, без долговременных записей. Deep:
  ранжирование + гейты + единственная запись (только в `MEMORY.md`).
- **Ранжирование Deep — шесть взвешенных сигналов**: relevance 0.30,
  frequency 0.24, query diversity 0.15, recency 0.15, consolidation
  (многодневные повторы) 0.10, conceptual richness 0.06 + бусты за фазы.
- **Гейты до модели**: minScore, minRecallCount, minUniqueQueries — все
  три обязаны пройти, иначе кандидат не доходит до модели вообще.
- **Ключевая архитектурная дисциплина: модель возвращает ОПЕРАЦИИ, не
  прозу**. Писатель применяет решения к файлу детерминированно, с
  ограничениями: `maxPriorEntryLossFraction` 0.25 (не потерять больше
  четверти прежних записей), `Source: path#Lx-Ly` на каждую запись,
  бюджет файла, структурный парс ответа. Прежняя версия `MEMORY.md`
  сохраняется в SQLite до записи; DREAMS.md получает added/merged/superseded
  счётчики (дифф-подсветка без копирования отклонённого).
- **Тайнт-гейт**: кандидаты с provenance `untrusted`/`system` удаляются
  до сборки промпта — структурно, не штрафом.
- **Ingestion элigibility**: только интерактивные сессии; cron/heartbeat/
  subagent исключены; повторно вызванный recall-контекст вычищается, чтобы
  его нельзя было «выучить заново».
- **Падение модели**: фолбэк на append-only путь; пустой прогон пишет
  завершение в plugin state без создания файлов.
- **Расписание**: один управляемый cron-джоб (`0 3 * * *`), дедуп по
  воркспейсам, doctor-ремонт исторических джобов, фоновая очередь
  сабагентов с приоритетом background.

### Letta (ex-MemGPT) — sleep-time compute
- Отдельный **sleep-time агент** правит память основного: структурные
  edit-tools (insert/replace/rethink/finish) над memory blocks; может быть
  другая модель и своя частота (Letta 0.7.0, апрель 2025).
- Исследовательская база: Lin et al., arXiv:2504.13171 — польза sleep-time
  compute коррелирует с **предсказуемостью следующего запроса** пользователя;
  до ~5x экономии test-time compute, +13–18% точности на stateful-задачах.
- Честные предупреждения: «research prototype», высокие token-затраты;
  failure mode — **расхождение sleep-агента** (другие инструкции →
  перезаписанные блоки «навыков»).

### Zep / Graphiti — temporal knowledge graph
- Эпизоды → граф сущностей/рёбер с **окнами валидности**: обновление факта
  инвалидирует прежний, а не перезаписывает (наш SUPERSEDES/архив-режим 9-2).
- Episode-level provenance: каждый факт трассируется до входного эпизода.
- Консолидация = инкрементальное построение графа; bi-temporal модель —
  единственная архитектура, отвечающая «что было истинно на дату X».

### Claude Auto Dream (Anthropic, 2026)
- Многофазный цикл: ориентация на текущее состояние проекта → прунинг
  устаревшего → слияние дублей → переупорядочивание против противоречий
  и token-отходов. Оценка на CL-Bench: записи вида «правило + доказательство».

### Классика (без свежих источников)
- **Generative Agents** (Park 2023): memory stream, importance × recency ×
  relevance, reflection-синтез высокоуровневых наблюдений.
- **MemoryBank**: кривая забывания Эббингауза + обновление памяти фидбеком
  пользователя (наш канал коррекций — строже: предложение → подпись).
- **A-MEM**: Zettelkasten-стиль атомарных заметок со связями.
- **SleepGate / LightMem** (2026): sleep-micro-cycles над KV-cache с
  forgetting gate — для нас вне скоупа (уровень модели, не памяти).

## Синтез поверх нашей базы (9-6)

Что перенимаем (с адаптацией к нашим гейтам):

1. **Фазовая модель Light→REM→Deep — да**, но наша нарезка дешевле:
   Light у нас = SQL-отбор дельты (контестед-кластеры, unrevised proposals,
   свежие эпизоды) — детерминированно, без модели; REM = модельная
   рефлексия только над отобранным; Deep = revision-предложения в очередь
   proposals kind=revision. Долговременная запись — только после подписи
   оператора (этого ни у кого нет; у всех выше дриминг пишет сам).
2. **«Модель возвращает операции, не прозу» — главный перенос**. Уже в спеке
   9-6 (action: promote/demote/link/archive). Дополнение из OpenClaw:
   писатель применяет операции детерминированно с ограничениями
   (потолок потерь прежних записей, обязательные source-refs, бюджет).
   Для нас: apply_signed в 9-4 исполняет DEPLOY — добавить лимиты потерь
   и обязательные proposal_refs при promote/squash (tier-2).
3. **Шесть взвешенных сигналов ранжирования — переносим почти дословно** в
   ранжирование входов сна (relevance/frequency/query-diversity/recency/
   consolidation/richness), плюс нашего седьмого нет ни у кого: **trust-
   телеметрия** (acceptance по классам из receipts) — мета-сигнал на
   генераторы и на сам сон.
4. **Гейты до модели — у нас уже есть** (дельта-порог, лимит позиций);
   добавить из OpenClaw minRecallCount-аналог: вход сна должен иметь ≥N
   подтверждающих сигналов, иначе даже не предлагается.
5. **Тайнт-гейт**: у нас аналог — permissions/origin матрица 9-3 + исключение
   untrusted/system provenance. Для сна: cron/heartbeat ходы не входят в
   корпус (как у OpenClaw интерактив-only), кроме self-review, чей выход —
   сам материал сна. Recall-поднятый контекст не «переучивается».
6. **Фолбэк и пустые прогоны**: пустой/упавший прогон = запись в state,
   ноль побочных эффектов (уже в спеке 9-6; OpenClaw подтверждает паттерн).
7. **Дневник сна**: DREAMS.md-аналог нам не нужен как отдельный файл —
   наш аудит-след сильнее: receipts-цепочка + proposal-строки с обоснованием.
   Но «объяснимость почему не промотировано» (counts по категориям отказа
   в Deep-отчёте) стоит добавить в отчёт пакета/selfreview_report (9-4б
   канал, если понадобится).

Что НЕ перенимаем и почему:

- **Цельный rewrite канон-файла с maxPriorEntryLossFraction** — у всех
  движков дриминг пишет напрямую; наш receipt-путь с ратификацией строже,
  wholesale-rewrite не нужен (ревизии атомарны).
- **Отдельный sleep-агент с другими инструкциями (Letta)** — их же
  failure mode (расхождение). У нас: тот же агент/модель, pinned-промпт,
  ограниченный toolset (гард из спеки 9-6).
- **KV-cache dreaming (SleepGate/LightMem)** — уровень модели, вне скоупа
  контура памяти.
- **Полноценный temporal KG (Graphiti)** — наш путь к графу идёт через
  Д1 (entity-индекс + декларации), tier-2; bi-temporal запросы пока не нужны.
- **Фиксированный ночной cron (0 3 * * *)** — у нас дельта-триггер;
  исследование подтверждает экономность (польза ∝ предсказуемость запроса,
  у нас сон по накопленному материалу).
