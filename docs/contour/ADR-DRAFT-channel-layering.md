# ADR (draft): Линия абстракций канала — транспорт / документ / политика / агент

- **Статус:** набросок ADR, утверждён Ram 19.11 (виза «зафиксировать, внедряем»)
- **Контекст:** анализ флагов контент-гейтинга telegram-канала (`mention_only`,
  `passive_group_context`, `voice_without_mention`), инцидент GPU-группы 19.11
  (бот отвечал на необращённые голосовые), PR #12201.
- **Распространение:** логика уровней — обязательный критерий для всех наших
  фиксов и реализаций в каналах и смежных подсистемах.

## Проблема

Внутренний пайплайн telegram-канала протёк: транспортное поле Telegram
(`message.voice`) выросло в поведенческую категорию с собственным парсером,
смешавшим три вещи с разными причинами изменения — декодирование платформы,
обработку документа (транскрипция) и политику участия (mention-гейт).
Симптом: каждая новая асимметрия требовала нового флага. Рваная матрица
покрытия: у text — «дроп | наблюдение», у voice — «ответ | дроп», у медиа —
только дроп. `voice_without_mention` (PR #12201) родился именно из этой
дыры — и предлагается не мёржить, а заменить этим рефакторингом.

## Тезис

Обращённость (addressed: mention / reply-to-bot) — свойство **сообщения**.
Формат нагрузки — свойство **документа**. Правила участия — свойство
**агента**. Три разных темпа изменения были слиты в одних функциях. Фикс —
восстановить однонаправленность слоёв внутри канала, чей контракт с
фреймворком (`ChannelMessage`) уже правильный. Канал слишком много знает о
Telegram; мы приводим его внутренности в соответствие с уже существующей
абстракцией фреймворка, не вводя новых сущностей.

## Линия абстракций (4 уровня)

Зависимости только вниз: L0 → L1 → L2 → L3. Ни один уровень не видит
словарь соседнего.

| Уровень | Имя | Знает | Делает | Меняется при |
|---|---|---|---|---|
| L0 | Транспорт (пер-канальный) | словарь платформы (поля Telegram, синтаксис mention, семантика reply) | platform JSON → `InboundMessage { sender, chat, addressed, text?, attachment_meta? }` | смене/добавлении платформы |
| L1 | Обработка документов (пер-форматный) | форматы нагрузки | `attachment_meta + bytes` → `Materialized { text_repr, local_path? }`; один процессор на тип: audio → транскрайбер, docx → конвертер, фото → путь/OCR | новом формате/процессоре |
| L2 | Политика участия (пер-канальный конфиг) | правила агентов: авторизация пиров, `mention_only` (когда отвечать), `passive_group_context` (что слушать) | `(is_group, addressed, cfg)` → `FullTurn \| Observe \| Drop`; один предикат, одна чистая матрица | смене правил участия |
| L3 | Рантайм агента | — | получает только FullTurn с готовым текстом/путями; контракт `ChannelMessage` не меняется | — |

Инвариант: «Что считается обращением» — семантика платформы, флаг
`addressed` вычисляется на L0. Сбои материализации (L1) — чистое I/O,
ретраи — оркестрация пайплайна, не парсеры. Voice-session UX (TTS-режим)
— про отправителя и модальность (`is_voice_peer`), живёт на стыке L0/L2,
не привязана к категории контента.

## План внедрения (4 ступени, каждая — отдельно ревьюабельный шаг)

1. **L2:** выделить `participation_policy(...)` + `addressed(...)`;
   подключить в `process_update` поверх существующих парсеров; матричные
   тесты 2×2×2. Нулевое изменение поведения.
2. **L1:** модуль материализации (скачивание, транскрипция, рендер
   `[Document: …]`, prepopulate как eager-вызов с cap-фиксом `761cdaeaa`).
3. **L0:** маппинг `voice|audio|document|photo|video` в одно attachment-
   семейство с payload_tag; удаление `try_parse_voice_message` как
   политического актора. Страховка — модульный сьют (500+ тестов).
4. **Конфиг:** удалить `voice_without_mention` из схемы и конфига.
   Апстримом ключ не выпущен (#12201 открыт) — deprecation-шим не нужен,
   это правка открытого PR.

## Поведенческие дельты (осознанные, одна)

Необращённый voice перестаёт получать немедленный ответ — следствие
инварианта «mention_only-бот не отвечает на необращённое ни в какой форме».

- **assist:** закрывается существующим `passive=true` — голос
  транскрибируется в контекст; LegalPlat «слышит всё», отвечает по обращению.
- **anim_studio:** **решение за Ram** — включить `passive_group_context`
  (слушать) или оставить дроп. Voice там реально используется (15 voice-туров
  в сессиях по 16.11).

## Нарратив для апстрим-PR

Заголовок: `channels/telegram: restore unidirectional layering of
transport, document processing and participation policy` (правка #12201,
`voice_without_mention` вынимается).

- **Problem:** category-per-transport-field → flag-per-asymmetry; every new
  payload format risked a new policy exception.
- **Thesis:** addressing is a message property; payload format is a document
  property; participation rules are an agent property — three different rates
  of change were fused; restore unidirectionality.
- **Why upstream wins:** новый формат = L1-only изменение без политического
  ревью; новая платформа = L0-only; политика = чистая матрица с тестами;
  L0/L1 — ровно та поверхность, которую реализует будущий WASM-плагин
  канала (channels — experimental tier, плагинная миграция на v1.0).
  Ноль новых публичных сущностей; один ключ отзывается до релиза.
- **Behavior guarantee:** семантика `mention_only`/`passive_group_context`
  не меняется; единственная дельта — исчезает незаадресованный voice-ответ.

## Чек-лист применения к новым фиксам (распространение логики)

Каждый новый фикс/фича в каналах проверяется по линии уровней:

1. К какому уровню относится изменение? (транспорт / формат / правила /
   агент)
2. Видит ли код словарь соседнего уровня? (поля Telegram в политике,
   mention-семантику в материализации, форматы в гейтах — запрещено)
3. Появился ли новый флаг? Если да — какая асимметрия слоёв его породила?
   Можно ли закрыть восстановлением границы вместо флага?
4. Категория контента не должна влиять на политику: text и любой
   attachment проходят одну и ту же матрицу L2.
