# ADR: Графовый слой в иерархии памяти агента

**Status:** Proposed (набросок — на ратификацию Ram)
**Date:** 2026-11-17
**Authors:** контур HC (Hermes, cachyos-srv) + контур RAM (windows-pc)
**Deciders:** Ram
**Consulted:** концепция семи пунктов (Фаза 1, закрыта синтезом), вердикт Фазы 2 (Deep Recon 2025–2026), KG-матрица grafeo-notebook vs gbrain (13.11), grafeo ADR-0034…0039, Layered Mutability (arXiv:2604.14717), Latent Identity Reversion (2610.01490), SIT (2609.22195), ForgetEval (2606.15903), практики Erkle/Estratos/Panella/Mem0/Graphiti
**Informed:** Hermes (identity-канон), grafeo-форк, ZeroClaw (MCP)

---

## Context

Психический скелет агента (L0 контекст → L1 рабочий стол → L2 архив →
L3 нарратив + ядро-регулятор SOUL.md) прокатан на живом агенте для слоёв
личности и памяти. Неосвоенным остался граф знаний. Фаза 1 сняла ложный
тезис «граф = верхний концептуальный слой» и установила: граф —
инфраструктура архива, не голос; нарратив меняется только ратификацией;
затухание обратимо. Фаза 2 показала: механики очереди и затухания у
рынка конвергентны (воруем), а ратификатора над нарративом нет ни у
кого (ниша, держим). Настоящий ADR размещает графовый слой в иерархии
и определяет протоколы, при которых он не может стать неподотчётным
соавтором идентичности.

Инструмент разреза, принятый обоими контурами: **граница слоёв — цена
изменения, а не тип данных.**

## Decision

### 1. РАЗМЕЩЕНИЕ

| Слой | Что живёт | Цена изменения | Кто пишет |
|---|---|---|---|
| L0 контекст | текущая сессия | ноль, не долговечно | среда |
| L1 рабочий стол | drafts, активные задачи | ноль | агент |
| brain.db (SQLite) | эпизоды (событийное зерно), core-записи, superseded_by | ноль, append-mostly | агент |
| **Граф (grafeo-форк)** | сущности, типизированные связи, статистика методов (успешность по опыту), консолидации | ноль на запись; чтение сложное | агент + dream-цикл |
| wiki (L2-компиляция) | тексты методов, концепты, сверстанные страницы | редакторская | агент с журналом |
| Очереди staging | image-pending.md (дельты нарратива), memory-write-gate | дешёвое накопление | агент, только propose |
| **L3 нарратив** | каноническая страница образа (wiki), версии | внимание человека | только протокол §2 |
| Ядро (SOUL.md) | миссия-аксиомы, принципы, полномочия | ратификация + redeploy | только протокол §2 |

Правило миграции: факт движется вверх по мере **дорожания цены его
изменения**, не по типу данных. Образец пути: удачный приём → эпизод в
brain.db → статистика метода в графе (после N повторений с исходом) →
текст метода в wiki (компиляция) → кандидат в принципы (дельта L3 в
очередь). Обратное движение — через затухание (§3), не через удаление.

Граница графа: в графе НЕ живут — эпизоды (зерно не то: триплет ≠
пережитое, Фаза 1 п.6), дельты нарратива (это очередь), принципы
(это ядро). Граф отвечает на вопрос «что связано с чем и как часто это
работало»; он не отвечает на вопрос «кто я».

### 2. ПРОТОКОЛ РАТИФИКАЦИИ (два ключа)

Писатель ≠ ратификатор. Первый ключ — агент (propose-only). Второй
ключ — операционный акт «утверждаю» Ram/Тимофея (не криптография, а
явное действие человека; криптографическая спина Panella-style —
опциональное ужесточение позже).

Протокол одной дельты:

```
1. PROPOSE   агент → image_delta_propose → image-pending.md
             (текст дельты + provenance + класс: образ/принцип/стиль)
2. MIRROR    decision_mirror собирает пакет на подпись (§4)
3. SIGN      оператор: «утверждаю» / «отклоняю» / «правлю и утверждаю»
4. RECEIPT   цепочка: (а) changelog канона (append, подпись, дата);
             (б) git-коммит в identity-репо (~/texts/Hermes/identity);
             (в) superseded_by в brain.db для замещённых записей;
             (г) затухание конфликтующих рёбер графа (§3)
5. DEPLOY    identity-doctor: OK → канон активен; провал → откат коммита
```

Запрещённые обходы (перечисление закрытых дверей):
- прямая правка канона агентом вне протокола (deploy.sh — только после SIGN);
- накопление мелких дельт до автоматического принятия (гейт §6.1:
  compositional drift — любая серия дельт суммарно меняющая образ
  требует одной явной подписи);
- ратификация через подчинённого агента (делегированная подпись
  не является подписью);
- MCP-путь: approval endpoints агенту не выдаются (разрез ключей
  на уровне инструментов, §5);
- правка истории ревизий (changelog и git — append-only).

Почва уже есть: identity-канон — git-репо с deploy.sh +
identity-doctor.sh; конституционное правило «одно согласие — одна
правка»; молчание ≠ согласие.

### 3. ЗАТУХАНИЕ — три механики одним дизайном

| Механика | Что делает | Что НЕ делает | Источник |
|---|---|---|---|
| decay-rerank | вес в поиске/предложениях 0.3–1.5x по использованию | не удаляет, не скрывает | Mem0 Decay |
| expiry | скрытие из выдачи после даты | fetch-by-ID всегда работает | Mem0 expiration_date |
| би-темпоральная инвалидация | valid time + transaction time; superseded_by | старое читается point-in-time | Graphiti + ADR-0035 |

**Обратимость — жёсткое требование.** Layered Mutability (hysteresis
0.68): после накопления памяти откат самоописания не восстанавливает
поведение — значит необратимое затухание превращается в скрытый дрейф.
Приёмочный тест: откат ратифицированной версии нарратива на копии
контура обязан вернуть поведение к поведенческой базовой линии
(набор пробных задач), иначе протокол затухания не принят.

Класс faded (отвергнутое ратифицированной версией): вес минимален,
из предложений не всплывает, пометка есть, прямой запрос `faded_get`
находит всегда. Удаление из класса faded — отдельная ратифицированная
дельта, не фоновый процесс.

### 4. ЗЕРКАЛО per-decision

Пакет на подпись (один экран, не сжатие графа):
1. текст дельты;
2. затрагиваемые узлы/рёбра графа с provenance («откуда ты» у каждого);
3. прогноз последствий: какие ответы/предложения изменятся, если
   подписать (и что изменится, если отклонить);
4. конфликты с действующим каноном (показать диффом);
5. что затухнет при подписи (faded-список этой дельты).

Зеркало генерируется по запросу ратификации, не живёт постоянно;
непросмотренное зеркало ≠ ратификация (подпись без сборки зеркала
протоколом не считается).

### 5. MCP-ПОВЕРХНОСТЬ (для ZeroClaw)

| Инструмент | Кто вызывает | Уровень | Что делает |
|---|---|---|---|
| `graph_query` | агент | L2 | чтение графа с decay-aware весами |
| `image_delta_propose` | агент | L2→очередь | единственный путь записи в сторону L3 |
| `decision_mirror` | агент/оператор | очередь | сборка пакета §4 |
| `faded_get` | агент/оператор | аудит | прямой запрос отвергнутого |
| `selfreview_run` | крон | сверка | недельная сверка + drift/hysteresis метрики (§6.1) |

Принципы поверхности: ни один инструмент не пишет в канон; очередь —
единственная дверь к L3; approval-инструментов в списке нет (они живут
вне MCP-поверхности агента — разрез ключей); каждый вызов атрибутируется
(кто предложил — в receipt).

### 6. ОТКАЗЫ И ГЕЙТЫ

1. **Compositional drift** (локально разумные правки без автора
   траектории). Метрика: доля изменений поведения, не покрытых
   receipt-записями; hysteresis-замер на недельном self-review
   (откат снапшота на копии → поведенческая дельта). Гейт: drift
   сверх порога → self-review эскалируется к человеку вне очереди.
2. **Self-sealing** (затухание без аудита). Запрет: нет записи —
   нет затухания. Гейт: аудит показывает faded_set непустым и
   находимым через `faded_get`.
3. **Забывание** (рынок: ForgetEval 7%). Гейт: на контрольном наборе
   faded-фактов прямой запрос находит ≥ 95% (цель — порядок выше
   рыночной практики).
4. **Потеря enacted-якоря** (Latent Identity Reversion: молчаливая
   реверсия в «голый ассистент»). SOUL.md — поведенческое состояние:
   детектор (self-id проба на восстановлении сессии), автовосстановление
   якоря из SOUL.md, инцидент — записью в brain.db. Гейт: probe после
   рестарта/восстановления сессии.
5. **Подпись без зеркала** — протокол не считает ратификацией (§4).

### 7. СВЯЗЬ С GRAFEO-ФОРКОМ

В существующий конвейер grafeo-форка (по матрице 13.11):
- ингест: чанкер/HNSW/rerank-протокол/промпт-контракт из gbrain-наследия;
- экстракционный каскад ADR-0037 (typed edges для графа агента);
- decay-rerank — в PageRank/PPR веса (topological-tools);
- би-темпоральность — расширение ADR-0035: + transaction time;
- sentence provenance — provenance зеркала §4;
- dream-цикл форка = консолидатор L2 (атомы→концепты); очередь L3 он
  НЕ трогает — граница Фазы 1 п.3.

Новый слой (агентный, поверх форка как сервиса): brain.db (эпизоды),
очередь image-pending, зеркало, receipt-цепочка, MCP-поверхность §5.
Grafeo — substrate, не продукт: продукт — контур памяти агента.

## Consequences

### Positive

- Граф получает законное место без претензии на голос; ратификация
  вооружена зеркалом и receipt-цепочкой; затухание обратимо и аудируемо.
- Все «ворованные» механики Фазы 2 ложатся поимённо в разделы 2–6.
- MCP-поверхность делает контур инструментом для других агентов
  (ZeroClaw) без открытия канона.

### Negative

- Два хранилища (brain.db + граф) требуют дисциплины «кто за что
  отвечает» — раздел 1 решает через цену изменения, но дрейф границ
  возможен; лечится тем же self-review.
- Зеркало per-decision — новый вычислительный узел; его качество
  (полнота прогноза) — открытый вопрос, гейтится практикой.

### Trade-offs accepted

- Второй ключ — операционный акт, не криптография (проще, достаточно
  для одного оператора; Panella-путь оставлен апгрейдом).
- Затухание обратимо, следовательно faded-хвост растёт; принимается
  как цена аудита.
