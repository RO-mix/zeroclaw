## Черновик видения — сторона RAM (код zeroclaw), для сложения с HC

**Горизонт 12 месяцев, целевое устройство памяти агента zeroclaw (как я вижу со стороны кода):**

1. **База не меняется:** SQLite повсюду (brain.db — эпизоды+proposals; knowledge.db — граф когда дойдёт), канон-файлы (SOUL/IDENTITY/AGENTS) — якорь, wiki — компиляция и нарратив. Никаких новых БД и сервисов.
2. **Инжект трёх скоростей:** (а) всегда — дистиллят нарратива с жёстким cap (Д3); (б) relevance-recall на сообщение с recall-гейтом покрытия (W5) — «помнит оператора через годы» = находимость в моменте; (в) explicit-доступ (fact_get/graft) для аудита и отвергнутого.
3. **Суждения (Д2 в финале):** пакетная ратификация с двойным триггером (календарь self-review ИЛИ событие-коррекция); генераторы: коррекции (явные + канал «diff без агента») → противоречия (conflict.rs) → дорогие эпизоды → trend-дно; throttle бюджета proposals/нед; отказ оператора — бессрочный записанный эпизод; stale proposals затухают-с-аудитом.
4. **Обратимость (Д4+W2):** retention = архивирование, не DELETE; версии change/end/correct/revert + present-only recall + as_of; гигиена несёт слой триггеров (ДT).
5. **Граф (Д1, когда созреет):** год первый — W4 entity-индекс поверх FTS (probe/reason-подобие), извлечение из ратифицированных суждений, гейт utility rate; полноценный KG — при мультиагентности.
6. **Полномочия (Д5):** категория×операция×origin; propose-only на суждениях/нарративе; forget/purge закрыты на них.
7. **Гейты:** находимость отвергнутого ≥95%; пакет acceptance ≥20%; self-id probe с негативными пробами; раздел нарратива «открыто/оспорено/не знаю».
