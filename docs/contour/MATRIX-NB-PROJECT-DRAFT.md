# ДРАФТ ПРОЕКТА: Matrix-контур на Nota Bene (агенты без Telegram)

Статус: **ДРАФТ / набросок + решения по открытым вопросам (13.11)**. Не согласовано окончательно, NB-контур НЕ уведомлён до фиксации PRD.
Зафиксировано: 13.11.2026, контур RAM-RAMII (w1). Исследование: `tasks/agent-niouxv3y/output.log`.

## Решения по открытым вопросам (13.11, Ram + Kimi)

1. **Homeserver: Synapse** (референс-реализация, максимум фич/MSC для опоры при
   доработке канала под Telegram-паритет; тяжелее Conduit — терпимо на VPS NB,
   нужен Postgres). **Federation ВЫКЛ для старта** — только локальные пользователи
   NB; включение — конфигурационное изменение в любой момент. (Conduit/Continuwuity
   отклонены: молодость, меньше обкатанная безопасность.)
2. **Операционка**: сервер администрирует агент Nota Bene (обновления, crypto-store,
   device-сессии ботов, backup recovery keys). Сервер включается в штат NB.
3. **Миграция**: все агенты уже перенесены в ZeroClaw на NB — задача сводится к
   созданию им адекватных Matrix-каналов. Дальше — зеркалирование.
4. **E2EE — смешанная политика**: внутренние/операционные комнаты БЕЗ E2EE
   (прозрачность для администрирования); клиентские комнаты с конфиденциальными
   данными — С E2EE (на VPS только шифротекст). Ключевой факт: observability
   живёт на стороне агента-клиента (runtime-trace), от E2EE не страдает; теряются
   только серверные логи содержимого зашифрованных комнат.
5. **Блокеры для тест-релиза нет**; план доработок канала уже есть (6 пробелов,
   ~500–1000 строк — см. таблицу ниже). edited_messages и owner-нотисы —
   первоочередные в бэклоге доработок.
6. **Пилот — сразу на сервере NB** (тоннель от нашего контура уже есть), без
   промежуточного пилота на RAM-RAMII.
7. **Клиенты**: протокол обеспечивает совместимость с любым клиентом. Рекомендация
   людям: Element X (Android/iOS), Element Desktop (Win/macOS/Linux), FluffyChat
   (простой Android), Nheko (альтернатива для продвинутых).
8. **Multi-tenancy (уточнить с NB-контуром)**: по аналогии с сериализацией
   ZeroClaw-инстансов — для каждой организации, заводимой в Nota Bene, по умолчанию
   предполагаем **свой Matrix-сервер** (per-org homeserver, тот же паттерн изоляции,
   что и у ZeroClaw). Однако Synapse внутри одного сервера умеет разделение на
   комнаты/пространства с разными политиками — если для нескольких организаций
   хватит одного сервера, оставляем один. **Решение за NB-контуром** при обсуждении
   PRD: изоляция per-org сильнее (компрометация сервера = только своя организация),
   один сервер дешевле в администрировании. Старт — один Synapse на NB-организацию.

## Цель проекта

На NB-контуре (cachyos-srv, VPS + stand) **нет Telegram** — агенты Nota Bene живут в
ZeroClaw-инстансе без внешнего мессенджерного подключения. Проект: поднять
Matrix-инфраструктуру на NB и перевести агентов с инстанса ZeroClaw Nota Bene на
Matrix как канал связи с людьми (команда NB, клиенты). Параллельно — пилот
интеграции Matrix-канал ZeroClaw в реальной эксплуатации.

## Мотивация (факты исследования 13.11)

- Matrix-канал ZeroClaw (`crates/zeroclaw-channels/src/matrix.rs`, 12,5K строк,
  274 теста) — production-ready: mention_only, реплаи, медиа в обе стороны,
  нативная voice-транскрипция (MSC3245), стриминг-драфты, peer_groups, pacing,
  полный E2EE через matrix-sdk (recovery key + cross-signing).
- Ядро агентного контура на Matrix работает из коробки — конфиг-only.
- Telegram на NB-контуре отсутствует физически (регион/блокировки) — Matrix
  (self-hosted, federation) — рабочий путь к людям.

## Открытые вопросы для сессии PRD (по BMad)

1. **Homeserver**: self-hosted Synapse на VPS NB? Conduit/Continuwuity (легче)?
   Публичный хост для пробы? Federation вкл/выкл?
2. **Операционка**: кто администрирует (обновления безопасности, crypto-store,
   device-сессии ботов, backup recovery keys)? NB-контур самостоятельно?
3. **Миграция**: какие NB-агенты первые (researcher? notabene-op?), порядок
   перевода, сохранение истории/памяти агентов.
4. **E2EE-политика**: зашифрованные комнаты для клиентских данных? Влияние на
   наблюдаемость/аудит (Демиург-аналог NB не читает E2EE без ключей).
5. **Пробелы канала**: какие из 6 доработок — блокеры для первого релиза,
   какие — бэклог? (edited_messages и owner-нотисы — кандидаты в блокеры.)
6. **Пилот на нашем контуре**: параллельный пилот Matrix у RAM-RAMII
   (first_contact, конфиг-only) как прогон перед NB — делаем или сразу на NB?
7. **Клиенты**: чем люди ходят в Matrix (Element X? Nheko? мобильные?).
